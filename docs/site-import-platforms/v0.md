## How sites on v0 are built

v0 (Vercel's AI builder, v0.dev, now v0.app) writes a **Next.js App Router** project — React Server
Components, Tailwind, shadcn/ui (Radix), lucide icons, Geist/Inter via `next/font` — and deploys it on
Vercel, by default at `v0-<project>.vercel.app`, often later on the owner's own domain.

- **Server-rendered.** Almost every word is in the HTML. The same tree is sent again as the React Server
  Components (RSC) payload: `<script>self.__next_f.push([1,"…"])</script>` chunks that join into rows of
  `id:value` (elements are `["$", type, key, props]`; `"$L5"` points at row 5; long text travels as
  `5:T<hex byte length>,<text>`).
- **Words that are only in the payload:** Radix accordions, collapsibles and tabs render their closed or
  inactive panels as **empty** boxes (`<div data-state="closed" role="region" hidden>`). shadcn's FAQ
  accordion is v0's standard FAQ, so the answers were all lost. Mobile menus (Radix Sheet) are not in the
  HTML at all, but the desktop menu (`nav.hidden.md:flex`) is.
- **Streamed Suspense content** arrives at the end of `<body>` as `<div hidden id="S:0">`, outside
  `<main>`; its "Loading…" fallback sits where it belongs between `<template id="B:0">` and `<!--/$-->`.
- **Pictures:** `next/image` writes `/_next/image?url=%2Fhero.jpg&w=3840&q=75` (+ a srcset of the same),
  though v0's default `next.config` often sets `images.unoptimized`, giving plain `/hero.jpg`. Uploads go to
  Vercel Blob (`*.public.blob.vercel-storage.com`). Unfinished v0 pages use v0's stock
  `/placeholder.svg?height=400&width=600`, `placeholder.jpg`, `placeholder-logo.png`, `placeholder-user.jpg`.
- **Menu:** usually a sticky `<header>` with `<nav>`; one-page v0 sites link to `#about`, `#services`.
- **Look:** Tailwind utility classes plus shadcn's theme variables in the compiled CSS
  (`/_next/static/css/*.css`): `--primary: 222.2 47.4% 11.2%` (bare HSL, Tailwind 3) or
  `--primary: oklch(0.205 0 0)` (Tailwind 4); arbitrary values like `bg-[#CCFF99]`. Fonts are self-hosted
  by `next/font` under hashed names (`__className_3a0388`, family `'__Inter_d65c78'`, `--font-geist-sans`).
- **Forms:** shadcn `<form>` with `Label` + `Input`, usually posting to a server action or nowhere.
- **Tell-tale markup:** `<meta name="generator" content="v0.app">` (older: `v0.dev`), added by v0 even
  when not in `layout.tsx`; the free plan's "Built with v0" badge
  (`v0.app/chat/api/open/built-with-v0/…`); `data-nimg`, `/_next/static/`, `__next_f`.

## Can be done (not done yet)

- **In-page anchor buttons on one-page sites** (S, `site-extract.ts`): `absolutise` returns null for
  `href="#menu"`, so a v0 hero button "See what we bake" is read as plain text, not a button. Map `#id` to
  the section on the same page (or to the home page) instead of dropping the link.
- **Logo through the adapter** (S, `site-extract.ts`): the logo uses `fullSizeImageUrl(src)`, not the
  adapter's `fullSize`. v0 is fixed by `prepare` rewriting `src`, but other adapters' `fullSizeImage`
  never reaches the logo. Change line ~763 to `logo = { src: fullSize(src), … }`.
- **shadcn theme colours** (M, `site-import-theme.ts`): read `--primary` / `--background` /
  `--foreground` from `:root` in the compiled CSS, in both shapes — bare HSL triples
  (`222.2 47.4% 11.2%`, which need `hsl(…)` around them) and `oklch(…)` (Tailwind 4 / new shadcn).
  Also Tailwind arbitrary colour classes on the body or hero (`bg-[#CCFF99]`).
- **`next/font` family names** (S, `site-import-theme.ts`): `'__Inter_d65c78'` / `'__Geist_Sans_abc'` →
  strip the leading `__` and trailing `_<hex>` and underscores → "Inter", "Geist Sans"; ignore
  `'… Fallback'` families.
- **Mobile-only menus** (M): a site whose only menu is a Radix Sheet has no menu in the HTML; its links are
  in the payload as children of the Sheet component. Rare on v0 (desktop `nav` is always there).

## Can't be done

- **Words held only in JavaScript bundles:** content written as a constant inside a `"use client"` file
  (e.g. `const faqs = [...]` in a client component), or behind `dynamic(…, { ssr: false })`, is in neither
  the HTML nor the payload. Only the headless browser (`site-js-render.ts`) can read it, and even then
  closed accordions stay closed. We don't fetch and run their bundles ourselves (no-script rule).
- **Data props:** words passed to a client component as plain data (`<Faq items={[{q, a}]} />`) are in
  the payload but not as elements, so we can't tell where they belong; left out rather than guessed.
- **Password-protected Vercel previews** (Vercel Authentication on preview deployments): a login page, no
  content.
- **Their form's backend:** server actions are code, not something we can copy; our contact form replaces
  it (already the import's behaviour).

## Suggested improvements to our import

The real fix for most of this is **generic Next.js handling**: everything this adapter does except the
badge, the placeholder pictures and detection applies to *every* Next.js App Router site (including
Lovable/Bolt/Cursor/Claude Code projects that chose Next.js, and hand-built ones):

1. **Unwrap `/_next/image?url=` in `fullSizeImageUrl`** (S, `site-extract.ts`) — today a plain Next.js
   site's pictures and logo are saved as resized wrappers (seen in `nextjs-plain.html`). Move
   `unwrapNextImage` from `v0.ts` into `site-extract.ts` (or a small `site-nextjs.ts`) and call it first in
   `fullSizeImageUrl`.
2. **Splice streamed Suspense boundaries before reading** (S, `readImportPage`) — `spliceStreamed` from
   `v0.ts` is React's own `$RC`; any React 18+ streaming site needs it.
3. **A shared `site-nextjs.ts`** (M) holding `readFlight`, `FlightRenderer`, `fillClosedPanels` and the
   thin-shell fallback, called from `readImportPage` whenever `self.__next_f` is present and no adapter
   has already done it. `readPage` in `site-import.ts` would then open the headless browser far less often
   for Next.js sites. The v0 adapter's `prepare` would shrink to the badge and placeholders.
4. **Radix closed panels on non-Next sites** (M): Vite + React sites (Lovable, Bolt) render the same empty
   accordion boxes but have no payload — the headless browser could click `[aria-expanded="false"]`
   triggers in `site-js-render.ts` before taking `page.content()`.

## Detection

`detect(html, gen)`:

1. `gen` (the generator tag) is `v0.app` or `v0.dev` → v0. v0 adds the tag to every page it builds.
2. Otherwise the page must be **Next.js** (`/_next/static/`, `self.__next_f.push`, or `__NEXT_DATA__`)
   **and** carry a v0 fingerprint: the "Built with v0" badge link or its `id="v0-built-with…"`, a
   `v0-*.vercel.app` address (canonical, og:url, links), v0's shared upload store
   `hebbkx1anhila5yf.public.blob.vercel-storage.com`, or v0's `placeholder.svg?height=` pictures (plain or
   inside `/_next/image?url=`).

False positives removed: pages that only mention or link to v0.app/v0.dev (template galleries, blogs,
hand-made sites) — the old test matched them. **False negatives, by design:** an owner who removed the
generator tag and the badge, moved to their own domain and replaced every placeholder has a site that is
indistinguishable from any Next.js site — which is why the generic Next.js handling above is the real fix.
Order in `index.ts` doesn't matter for v0 (no other adapter matches Next.js markup today).
